# משימת פיתוח 014א: שאלה מנחה ושלב חילוץ לתאריכים ולנוסעים (שלב 1)

**תוכנית:** [014](../plans/014-guided-questions-structured-understanding.md). אושרה ב-16.10 על ידי בעלת העסק, דרך שלמה.
**▶️ מתחילים עכשיו (16.10, החלטת בעלת העסק "עכשיו", כחריגה מההקפאה).** הועבר לבצלאל.
**עיקרון מנחה (בעלת העסק):** איכות ההבנה קודמת לחיסכון.

## היקף
- רק שתי שאלות בסיס: **תאריכים** ו**נוסעים**.
- יעד, סוג נסיעה והשירותים נשארים בקוד הקיים. הם ייכנסו בשלבים הבאים.

## 1. הדגל
- משתנה סביבה: `GUIDED_EXTRACTION_STEPS`, רשימה מופרדת בפסיקים. ברירת המחדל ריקה, כלומר הכל עובד כמו היום.
- בשלב הזה הערכים האפשריים הם `dates` ו-`travelers`, למשל `GUIDED_EXTRACTION_STEPS=dates,travelers`.
- **כשהדגל לא כולל שאלה:** ה-regex ו-`_deterministic_date_facts` / `_deterministic_duration_facts` הקיימים עובדים כמו היום, **בלי שום שינוי**.
- **כשהדגל כולל שאלה:** החילוץ החדש הוא מקור האמת לשאלה הזו. ה-regex הקיים לאותה שאלה לא רץ (מדלגים עליו, לא מוחקים אותו).

## 2. שינויים ב-trip_state
- **השדות הקיימים לא משתנים:** `dates` (departure, return, period, flexibility_days, duration_days, constraints) ו-`travelers` (adults, children, child_ages, child_genders, infants, composition). החילוץ ממלא אותם.
- **שדה חדש אחד:** `guided`
```json
"guided": {
  "current_question": "dates" | "travelers" | null,
  "attempts": 0,
  "answered": ["dates"]
}
```
- `current_question` נקבע כשאריאלה שואלת את השאלה, ומתאפס אחרי חילוץ מוצלח.
- `attempts` נספר רק ל-`unclear`. אחרי 2 ניסיונות לא ברורים מציעים אפשרויות לבחירה (סעיף 5).

## 3. מתי שואלים
- כשהדגל פעיל, השדה עדיין חסר, ואין שאלה פתוחה אחרת, **אריאלה שואלת על הפרט הבא בלבד.** **אריאלה מנסחת בעצמה** ([PRODUCT_RULES](../PRODUCT_RULES.md) §2). הקוד **לא** שולח משפט קבוע.
  - **איך:** הקוד קובע את `guided.current_question`, ומוסיף ל-`system_dynamic` עיקרון קצר. למשל: "הפרט הבא לברר: מועד היציאה ומשך החופשה. שאלי עליו שאלה אחת, פתוחה, בניסוח שלך, ואפשר עם דוגמה קצרה. אל תשאלי 'א או ב'."
  - **להמחשה בלבד, לא כטקסט קבוע:** "מתי תרצו לצאת, ולכמה לילות?" או "מי מצטרף לחופשה?".
- **הסדר:** קודם תאריכים, אחר כך נוסעים, אחרי שהיעד ידוע (כמו היום).
- **אם הלקוח כבר מסר את הפרט** קודם, ובוודאות (`confidence:"high"`), מדלגים על השאלה.

## 4. החילוץ (schema)
- קריאה נפרדת לפונקציה הקיימת `_post_claude`, עם `source="guided_extract"` (לרישום ב-ai_usage).
- **המודל:** `GUIDED_EXTRACTION_MODEL`, וברירת המחדל זהה למודל הראשי `ARIELLA_MODEL` (כיום claude-sonnet-5), לא מודל קטן. הסיבה: החלטת בעלת העסק, איכות לפני עלות.
- **הקלט:**
  - השאלה הנוכחית ותשובת הלקוח.
  - `today` (תאריך ישראל).
  - ה-state הנוכחי של `dates` ו-`travelers`, כדי לזהות תיקון.
  - 4 ההודעות האחרונות, כדי להבין הקשר.
- **max_tokens:** 300.
- **הפלט: JSON בלבד.**

### שאלת תאריכים
```json
{
  "status": "answered" | "unclear" | "other_topic",
  "departure": "YYYY-MM-DD" | null,
  "return": "YYYY-MM-DD" | null,
  "nights": int | null,
  "period": "טקסט חופשי, אם נמסר רק חודש או עונה" | null,
  "flexibility_days": int | null,
  "confidence": "high" | "low",
  "also_mentioned": { "travelers": {...} | null },
  "correction": { "field": "...", "old": ..., "new": ... } | null
}
```
### שאלת נוסעים
```json
{
  "status": "answered" | "unclear" | "other_topic",
  "adults": int | null,
  "children": int | null,
  "child_ages": [int, ...],
  "child_genders": ["male"|"female"|null, ...],
  "infants": int | null,
  "confidence": "high" | "low",
  "also_mentioned": { "dates": {...} | null },
  "correction": {...} | null
}
```
- **כללי ה-prompt:**
  - **"זוג"** = 2 מבוגרים. **"אני והבן שלי בן 9"** = 1 מבוגר, 1 ילד, ages=[9], genders=["male"].
  - **אסור להמציא.** כשחסר נתון: null, ו-`confidence:"low"`.
  - **ולידציה של תאריכים:**
    - departure לא בעבר, return אחרי departure.
    - אם יש nights ואין return, מחשבים return בקוד, לא במודל.
  - **`also_mentioned`:** רק פרטים שהלקוח אמר במפורש, בלי השלמות.

## 5. טיפול בתוצאה
| מצב | פעולה |
|---|---|
| `answered` + `high` | כותבים ל-state, מוסיפים ל-`guided.answered`, ועוברים לשאלה הבאה. |
| `answered` + `low` | אריאלה מבקשת אישור על **הפרט שהבינה**, בשאלת כן/לא אחת בניסוח שלה (להמחשה: "רק לוודא, יוצאים ב-10.11 ל-5 לילות?"). כפתורי עזר: [כן] [לתקן]. |
| `unclear` | אריאלה שואלת שוב, פשוט יותר, בניסוח שלה, ו-`attempts++`. אחרי 2 מוסיפים **כפתורי עזר** מתחת לשאלה פתוחה שהיא מנסחת. הכפתורים נקבעים בקוד, למשל חודשים קרובים או [1] [2] [3+] מבוגרים. **אסור "א או ב?" בשאלה עצמה.** |
| `other_topic` | לא נוגעים בשדה. הניתוב הקיים מטפל בהודעה, והשאלה נשארת פתוחה לתור הבא. |
| `also_mentioned` | שומרים רק פריטים עם high, ומדלגים על השאלה שלהם. |
| `correction` | מעדכנים את השדה. אריאלה מאשרת את העדכון במשפט קצר בניסוח שלה. אם השדה כבר שימש לשירות שנסגר (טיסה), מסמנים את השירות כצריך עדכון לפני הסיכום. |
| JSON לא תקין או שגיאה | **fail-safe:** חוזרים ל-regex הקיים לאותה הודעה, ורושמים warning. |

## 6. בלי לגעת
- "מאשרת" לפני סריקה, ו"הסר"/"עצור" (003ב), נשארים כללים קשיחים.
- היעד, השירותים והסיכום נשארים בקוד הקיים.
- לא מוחקים regex בשלב הזה.

## 7. בדיקות לשקד (גם עם הדגל וגם בלעדיו)
- **בלי הדגל:** כל חבילת ה-QA הקיימת (qa/run_qa.py) עוברת **בלי שינוי בתוצאות**.
- **עם `GUIDED_EXTRACTION_STEPS=dates,travelers`:**
  1. "10 בנובמבר ל-5 לילות" → departure=2026-11-10, return=2026-11-15.
  2. "באמצע נובמבר, בערך שבוע" → `low` + שאלת אישור. אין המצאה של תאריך מדויק.
  3. "14-16.3" → 2 לילות (באג קודם, regression).
  4. "זוג עם ילדה בת 17" → 2 מבוגרים, children=1, ages=[17], genders=["female"].
  5. "אני והתאומים בני 7" → 1 מבוגר, 2 ילדים, ages=[7,7].
  6. בשאלת התאריכים: "10.11, אני ובעלי ושני ילדים בני 5 ו-8" → תאריכים, ו-`also_mentioned`. שאלת הנוסעים מדולגת.
  7. אחרי שנקבעו 2 נוסעים: "רגע, שלושה" → correction, ו"עדכנתי: 3 נוסעים".
  8. "אין לי מושג" פעמיים → אחרי הפעם השנייה מוצגת שאלה פתוחה עם כפתורים. בודקים שהטקסט של השאלה **לא** כולל "או".
  11. **כלל "אפשרות אחת":** עוברים על כל השאלות שאריאלה שאלה בתרחישים 1–10. כל אחת היא שאלה פתוחה או כן/לא על אפשרות אחת. אישור עם low הוא "רק לוודא: יוצאים ב-10.11 ל-5 לילות?" [כן] [לתקן], ולא "10.11 או 11.11?".
  9. "כמה עולה מלון שם?" בזמן שאלת התאריכים → `other_topic`. השאלה נשארת פתוחה.
  10. סימולציה של JSON שבור → חזרה ל-regex, בלי קריסה.
- **מדידה:** בכל תרחיש בודקים את מספר הטוקנים ב-/admin/ai-usage (source=guided_extract) ומדווחים ממוצע.

## כלל ברזל (16.10)
