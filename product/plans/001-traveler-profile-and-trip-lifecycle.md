## עדכון 2026-10-08 — כיוון חדש לשלב 1 (לפי בעלת העסק)
בעלת העסק **לא** רוצה לשאול "הזמנת?". במקום זה:
1. **זיהוי הזמנה לפי קרדיט מהשותף**: הקישורים למלון ולרכב כבר יוצאים דרך CJ עם `sid=trip{id}` (public_site.py:204–214, 4600–4610, 4650–4656). דוח העמלות של CJ מחזיר את ה-sid, כך שאפשר לדעת איזו חופשה הוזמנה בפועל — בלי לשאול את הלקוח.
2. **כשמתקבל קרדיט** → הודעת וואטסאפ חמה: "איזה כיף, ההזמנה נקלטה! 🎉 שתהיה לכם חופשה מושלמת ב{יעד}…".
3. **אחרי תאריך החזרה** → "ברוכים השבים! איך היה ב{יעד}?" עם כפתורי דירוג.
צריך לבדוק: גישה ל-API של דוחות CJ (מפתח API), תוך כמה זמן העמלה מופיעה, ואם גם טיסות עוברות דרך שותף שמחזיר קרדיט (נראה שכרגע רק מלון ורכב).

## הבעיה / ההזדמנות
- אריאלה **לא יודעת אם הלקוח הזמין**. היום נרשמת רק לחיצה על "להזמנה" בטבלת `booking_clicks` (database.py:323) — לחיצה, לא הזמנה.
- ההעדפות של הלקוח נשמרות **לכל חופשה בנפרד** (`trip_requests.answers_json`, `ariella_trip_conversations.profile_json`) ולא כפרופיל קבוע. בחופשה הבאה אריאלה עלולה לשאול שוב דברים ידועים.
- המשוב (`feedback_messages`, database.py:355) הוא טופס צור-קשר כללי: לא מקושר ללקוח או לחופשה, בלי דירוג.
- צ'טים חופשיים כבר זוכרים שיחות — ולכן הזיכרון לבד לא מבדל. מה שמבדל: זיכרון **מובנה** שקשור לחופשות אמיתיות, מחירים אמיתיים, ומה קרה בפועל בטיול.

## מה הלקוח יחווה (תרחיש)
1. דנה לוחצת "להזמנה" על טיסה לאתונה. יום אחרי (בוואטסאפ או בכניסה הבאה לאתר): "הספקת להזמין את אתונה? 🙂 [כן, הזמנתי] [עוד לא] [החלטתי לוותר]".
2. "כן" → החופשה מסומנת "הוזמנה" ומופיעה ב"החופשות שלי" עם ספירה לאחור.
3. יומיים אחרי תאריך החזרה: "ברוכים השבים! איך היה באתונה? ⭐1–5" + שאלה אחת פתוחה ("מה הכי אהבת / מה פחות?").
4. בחופשה הבאה: "בפעם הקודמת אהבת שהמלון היה במרכז ולא אהבת טיסת לילה — לחפש שוב ככה?"

## למה זה מבדל מצ'ט חופשי
- צ'ט לא יודע שהלקוח טס בפועל, מתי, ועם מי. אריאלה כן — כי היא בנתה את החופשה.
- המשוב משפר גם את הניקוד והמלצות היעדים לכל הלקוחות (מידע שאף צ'ט כללי לא אוסף).

## מה קיים היום בקוד
- `members` (שם, אימייל, טלפון, מגדר), `ariella_travel_companions` (שמות נלווים בהסכמה), `trip_requests`, `ariella_conversations`, `ariella_trip_conversations`, `booking_clicks`, `payments` (תשלום על חיפוש — לא הזמנת חופשה), `feedback_messages`.
- טינקרבל כבר מחלצת פרופיל מובנה מהשיחה (travel_agents.py, TINKERBELL_SYSTEM).

## שינויים נדרשים
### נתונים
1. **`traveler_profiles`** — פרופיל קבוע לכל לקוח (שורה אחת, JSON + זמן עדכון):
   - הרכב נסיעה רגיל: מבוגרים, גילאי ילדים (שנת לידה, לא גיל — כדי שיתעדכן לבד).
   - שדות תעופה: שדה המראה מועדף, טיסה ישירה בלבד / מקס' עצירות, שעות מועדפות ("לא טיסות לילה"), כבודה רגילה, חברות אהובות/לא.
   - לינה: סוג (מלון/דירה), דירוג כוכבים, מיקום, ארוחות.
   - סגנון: בטן־גב / ערים / טבע / סקי, קצב, נגישות.
   - תקציב טיפוסי לאדם.
   - מגבלות: כשרות, שבת, נגישות — **רק אם הלקוח אמר במפורש**.
   - יעדים שביקר בהם ויעדים ברשימת חלומות.
   - לכל שדה: מקור (`said_in_chat` / `questionnaire` / `inferred_from_feedback`) ותאריך — כדי שאפשר יהיה להציג ולתקן.
2. **הרחבת `trip_requests`** בעמודות: `lifecycle_status` (planning / clicked / booked / upcoming / travelling / returned / reviewed / cancelled / not_booked), `booked_confirmed_at`, `outbound_date`, `return_date`, `destination_code`, `next_check_at`.
3. **`trip_feedback`** — member_id, trip_id, דירוג 1–5, דירוג לכל רכיב (טיסה/לינה/מסלול/אריאלה), טקסט חופשי, created_at.
4. **הרחבת `feedback_messages`** בעמודות אופציונליות `member_id`, `trip_id`, `rating` — כך שהטופס הקיים ימשיך לעבוד, ולקוח מחובר יקושר אוטומטית.
- כל השינויים כ-`ALTER TABLE`/`CREATE TABLE IF NOT EXISTS` בסגנון המיגרציות הקיים ב-database.py.

### לוגיקה
- **עדכון פרופיל**: בסוף כל שיחה/חופשה, מעבר על ה-profile של החופשה והעתקת העדפות *יציבות* (לא תאריכים ויעד) לפרופיל הקבוע. העדפה חדשה גוברת על ישנה.
- **שימוש בפרופיל**: בתחילת חופשה חדשה הפרופיל נטען ל-profile ההתחלתי, ואריאלה **מאשרת** במשפט אחד במקום לשאול ("כמו בפעם הקודמת — 2 מבוגרים ו-2 ילדים, טיסה ישירה?").
- **מחזור חיים**: משימה יומית (קיים scheduler.py) שעוברת על חופשות לפי `next_check_at`:
  - clicked + יום אחד → שאלה "הספקת להזמין?" (פעם אחת, תזכורת אחת לכל היותר).
  - booked + תאריך יציאה עבר → travelling; תאריך חזרה + 2 ימים → returned → שאלת "איך היה?".
- **מקורות אישור הזמנה** (מהקל לכבד): (א) הלקוח מאשר בלחיצה; (ב) דוחות שותפים (Booking affiliate וכו') כשיהיו; (ג) בעתיד — webhook מ-B-Agent.

### ממשק (אתר / וואטסאפ)
- באזור האישי: "הפרופיל שלי" — מה אריאלה זוכרת עליי, עם אפשרות לערוך ולמחוק כל שורה.
- "החופשות שלי": סטטוס, ספירה לאחור, כפתורי "הזמנתי" / "לא הזמנתי".
- כרטיס "איך היה?" באזור האישי ובוואטסאפ (כשהחיבור יהיה מלא).
- עד שהוואטסאפ מחובר: השאלות מוצגות בכניסה הבאה לאתר ובמייל (קיימת תשתית מייל של טופס המשוב).
